## 1. 结论摘要

设计阶段只保留两个用户可见产物：

1. **实体设计**：表/实体、字段、类型、必填/唯一/默认值、实体关系（ER）。
2. **页面原型**：按场景/业务流程生成页面原型（列表、创建弹窗、编辑、详情等），以图片/可视化原型呈现。

但建议在图片背后保留一份**结构化页面规格**（页面类型、绑定实体、字段、动作、空/错/加载状态、验收），否则图片无法精确交给开发。用户可以只感知“图片”，开发交接时同时拿到图片 + HTML/页面规格。

**推荐技术路线：不调用图片生成模型，而是用 HTML/CSS 线框原型 + 浏览器截图生成图片。** 现有代码已经有 `PrototypeRenderer` 和 `WireframeTable/Form/Detail/Dashboard...`，可以复用并加“企业级”皮肤；这样文字清晰、可编辑、可重复生成，避免图片模型把字段名画错。原型也采用模板：应用选择原型模板，模板决定页面集、布局和风格，后续开发按该模板生成的原型/规格实现。

## 3. 实体设计

### 3.1 内容

- 应用级实体（不是每个场景重复建），场景通过引用使用。
- 实体：名称、表名（可选）、描述、所属场景/需求点。
- 字段：名称、显示名、类型、长度/精度、必填、唯一、默认值、枚举/字典、引用实体、校验/备注。
- 关系：1:1、1:N、N:1、N:N；外键字段、关系名称；ER 图展示。
- 可选：索引、唯一约束、状态字段；先不做复杂数据库特性。

### 3.2 交互

- 左侧实体列表 + 搜索；中间字段表格；右侧/下方 ER 关系图。
- 新增/删除实体、字段；拖拽排序；关系连线或表单选择。
- “问 AI”：按实体/字段聚焦，AI 修改字段/关系。
- 校验：实体名/表名唯一、字段名唯一、ref 目标存在、主键存在、类型合法。
- 确认：实体设计可整体确认，也可逐实体确认；确认后仍可修改（设计阶段未完成前）。

### 3.3 复用

- 现有 `EntityRelationGraph.vue`、`EntitySection.vue`、`DataModelPanel.vue` 可作为基础；
- 新设计阶段只保留实体相关能力，隐藏旧规格池/类型树；
- 数据结构可先复用 `SpecEntity/SpecField/SpecRelation`，再简化 UI。

## 4. 页面原型

### 4.1 页面集

按场景/业务流程生成：

- 列表页（查询、分页、操作列）
- 创建表单（弹窗或页面）
- 编辑表单（弹窗或页面）
- 详情页
- 可选：仪表盘/看板/甘特/日历（按业务需要）

示例：订单管理 → 订单列表、创建订单（弹窗表单）、编辑订单、订单详情。

### 4.2 原型形态

推荐两种视图：

- **实时 HTML 原型**：在画布中直接渲染，可缩放、可交互（示意动作）、可批注；
- **图片快照**：把 HTML 原型截图成 PNG，作为“页面原型图片”展示/导出/进入交接包。

为什么不用图片生成模型：

- 文字/字段名容易画错，企业表单尤其明显；
- 图片不可编辑，改一个字段要重新生成整张；
- 图片无法精确表达字段类型、校验、动作；开发需要结构化页面规格；
- HTML 原型可确定性重渲染，适合版本 diff 和交接包。

实现：

- 复用 `PrototypeRenderer.vue` + `WireframeTable/Form/Detail/Dashboard...`；
- 增加“企业级专业管理风格”皮肤（配色/字体/间距/表头/按钮），先做 1—2 套；
- 截图可用前端 `html2canvas` 或后端 Playwright（二选一，后续决定）；
- 图片存应用目录 `docs/design/prototypes/` 或数据目录，DB 存元数据/path/hash，不把 base64 塞 SQLite。

### 4.3 页面规格（图片背后的结构化数据）

每个原型保留：

- 页面标题、类型、绑定实体、所属场景/Epic；
- 字段列表/布局（表格列、表单分组、详情字段）；
- 动作（新建/编辑/删除/详情/导出等）；
- 状态（加载/空/错误/无权限）；
- 验收标准/批注；
- 风格/版本/截图路径。

这些数据用于：

- 重新渲染原型；
- 设计阶段确认/评审；
- 开发交接（图片 + HTML + 页面规格 + 验收）。

### 4.4 交互

- 场景/Epic 列表 → 页面列表 → 选中页面看原型；
- 风格选择、缩放、全屏；
- “问 AI”按页面聚焦：改字段/布局/文案/状态，重新渲染；
- 手动编辑页面规格（字段、动作、状态），重新渲染；
- 确认页面原型；可批量确认；
- 版本/回滚（复用 R1 文档版本思路，或按页面版本）。

### 4.5 原型模板（本次新增，和需求模板同思路）

原型也要像需求阶段一样采用模板：**模板决定页面集结构、布局模式、视觉风格和组件约定**；应用只保存“使用哪个原型模板”。开发阶段后续按这个模板生成的原型/页面规格来实现，保证风格一致。

模板内容建议分四层：

1. **App Shell（应用外壳）**
   - 侧边栏 / 顶栏 / 面包屑 / 页面标题 / 内容宽度；
   - 桌面 / 移动端（先桌面）。
2. **页面模式（按页面类型）**
   - 列表：筛选区、表格列、行操作、批量操作、分页、空/错/加载；
   - 表单（页面或弹窗）：字段分组、标签位置、输入宽度、校验提示、底部按钮；
   - 详情：头部、分区、描述列表、关联列表、操作；
   - 仪表盘/看板等按需。
3. **设计 Token**
   - 主色、辅助色、中性色、字体、圆角、间距、密度（紧凑/舒适）、按钮/表格/标签风格。
4. **页面集规则**
   - 每个场景/Epic 默认生成哪些页面（列表 + 创建弹窗 + 编辑 + 详情）；
   - 创建/编辑是弹窗还是独立页面；
   - 命名规则、默认分页、默认搜索字段；
   - 给 AI 的模板提示词。

模板数据结构（建议）：

```ts
interface PrototypeTemplate {
  id: string
  name: string
  category: 'enterprise' | 'minimal' | 'mobile' | 'custom'
  description: string
  tokens: {
    primary: string
    neutral: string
    font: string
    radius: number
    spacing: number
    density: 'compact' | 'comfortable'
  }
  shell: { type: 'sidebar' | 'topbar'; sidebarDark: boolean; contentWidth?: number }
  patterns: {
    list: { filters: boolean; rowActions: boolean; pagination: boolean; selection?: boolean }
    form: { presentation: 'dialog' | 'page'; labelPosition: 'top' | 'left'; groups: boolean }
    detail: { sections: boolean; relatedLists?: boolean }
  }
  pageSetRules: {
    defaultPages: Array<'list' | 'form' | 'detail'>
    createAs: 'dialog' | 'page'
    editAs: 'dialog' | 'page'
  }
  prompt: string
  builtin: boolean
  visibility: 'builtin' | 'private'
  previewPath?: string       // 模板预览图
  createdAt: string
  updatedAt: string
}
```

首批内置原型模板建议：

| 模板 | 风格 | 适用 |
| --- | --- | --- |
| 企业级专业管理 | 深色侧栏、白色内容、紧凑表格、蓝色主色 | 后台管理系统（默认） |
| 简洁后台 | 浅色侧栏、留白多、轻边框 | 中小型业务系统 |
| 移动端管理（后续） | 手机壳、底部标签栏 | 移动端场景 |

模板中心与需求模板一致：

- 全局库 + 应用只保存 `prototype_template_id`；
- 内置只读；复制为“我的模板”后可改 token/模式/页面集规则；
- 搜索/分类/预览/使用中；
- 切换模板：按页面 key/标题保留页面规格，重新渲染原型，生成新版本；旧版本可回滚。

### 4.6 页面集粒度

- 以“场景/Epic → 页面集”为生成和修改单位：默认包含列表、创建、编辑、详情。
- 用户可以在页面集里增删页面、调整顺序；可以让 AI **整组重新生成**，也可以只改单个页面。
- AI 修改默认以页面集为上下文：知道同组页面之间的关系（列表→创建→编辑→详情）。
- 页面集状态：未生成 / 待确认 / 已确认 / 无需原型。
- 页面集确认后，单页仍可修改；修改会重置该页/该组确认状态。

### 8.1 版本策略（R2c，2026-11-11 更新）

设计项目版本从“每次保存都 +1”改为 **checkpoint 化**（与 R2b 需求文档一致）：

- **自动保存不产版本**：实体、页面、页面集的普通保存只更新内容与 `updated_at`；单实体/页面/页面集确认也是中间状态，不产版本。
- **关键节点产来源化版本**：确认设计（`confirm`，总是 +1，供 C1 `base_design_version`/取消恢复）、切换原型模板（`template-change`）、AI 生成/应用实体或页面集（`ai`）、同步设计输入（`sync`）、版本回滚（`rollback`）、变更取消恢复（`restore`）、手动“保存版本”/默认页面集生成（`manual`）。
- **手动保存版本**：`POST /api/apps/:id/design/versions`，draft 时快照当前实体/页面集，confirmed 409（确认版本已存在）。
- **版本列表**：带来源与所属变更单（`changeSetSeq/changeSetTitle`，LEFT JOIN `app_change_sets`），UI 显示“确认设计/AI 生成/模板切换/同步设计输入/版本回滚/变更取消恢复/手动保存”和 `变更 #N`。
- **快照范围**：只含实体/页面集规格，**不含原型 PNG/HTML**；回滚只恢复规格，不恢复截图（截图仍按页面另行存档/重截）。
- 不删除/压缩历史版本；交接包版本（`design_handoffs`）语义不变。
